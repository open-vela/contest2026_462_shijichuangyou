# 空闲熄屏与唤醒策略

对应需求 FR-08（P0）与执行手册 §10.1／§10.2。

## 为什么分成三层

手册明确要求分别验收，并给出两条反例：

> 全黑图像不是 L2 充分证据，L2 也不是 L3 充分证据。

所以"画面变黑了"不能算省电。本项目只实现 **L1 和 L2**，**不声明 L3**。

| 层 | 含义 | 本项目 | 实现方式 |
| --- | --- | --- | --- |
| L1 | 停止高成本动画、降低刷新 | **已实现** | 停止立绘换帧动画 + 叠加变暗遮罩 |
| L2 | 正确调用显示电源，屏幕真正关闭 | **已实现** | `ioctl(/dev/lcd0, LCDDEVIO_SETPOWER, 0)` |
| L3 | 系统进入可恢复的低功耗状态 | **未实现** | 不冒充；未做任何 suspend 声明 |

## 策略

默认 15 秒变暗、30 秒熄屏（手册建议值）。本项目是**佩戴展示物**，手册特别指出
不能默认几秒就熄屏导致无法展示，因此：

- 两个阈值都支持置 0 表示**禁用该级**，常亮模式不需要第二条代码路径；
- 变暗后角色名、文案与指示点仍然可读，只是整体压暗。

## L2 为什么是真的

"关屏"只有一条 openvela 路径，且设备名来自驱动源码而非猜测：

```
drivers/lcd/lcd_dev.c        case LCDDEVIO_SETPOWER -> lcd_ptr->setpower()
vendor/sifli/.../lcd/sf32lb_lcd.c   sf32lb_lcd_setpower() -> DisplayOn/Off
drivers/lcd/lcd_dev.c        snprintf(devname, "/dev/lcd%i", devno)
```

`ui/ebadge_display.c` 打开 `/dev/lcd0` 并下发 `LCDDEVIO_SETPOWER`。

**已知边界（诚实记录）**：`sf32lb_lcd_setpower()` 只做面板 DisplayOn/Off，
**不含亮度调节**。CO5300 是 AMOLED（自发光），且 openvela 的 vendor 树里
**没有**厂商 RT-Thread 固件中的 `lcdlight` 背光设备。因此本项目**没有亮度级**，
只有开关；"变暗"是遮罩，属于 L1 而非 L2。

设备打开或 ioctl 失败时，`ebadge_display_off()` **返回失败**并记录原因，
不会静默假装成功。原因显示在"配色"页底部一行（`ebadge_display_status()`），
便于真机验收时直接判读。

## 唤醒行为

- **触摸唤醒**：熄屏后触摸仍然到达手势回调，因为主循环独立调用
  `lv_timer_handler()`（`ebadge_main.c:72`），不依赖本视图的帧定时器。
  熄屏时暂停帧定时器（`lv_timer_pause`）以停止重绘。
- **唤醒的那一次触摸被吞掉**：手册要求"唤醒按键默认只唤醒，不同时执行换角色"，
  否则一次动作会产生两种不易预测的结果。因此从熄屏恢复时，该次触摸不触发任何
  手势；而**从变暗恢复不吞触摸**，因为画面仍可见，用户看得见自己在点什么。
- 恢复后重置空闲计时，并显示熄屏前最后的角色（角色状态本就不因熄屏而改变）。

## 未验证点（必须由真机确认）

- `/dev/lcd0` 在本固件中是否真的注册（配置项 `CONFIG_LCD_DEV=y` 已开，但**未实测**）；
- 熄屏后触摸控制器是否仍上报事件（触摸控制器是独立 I2C 器件，理论上仍工作，
  **未实测**）；
- 面板 DisplayOff 的实际功耗下降未测量，因此**不给出任何续航数字**。

## 主机可测部分

空闲状态机是纯整数运算，已从 UI 中拆出（`core/ebadge_power.c`）并由
`tools/run_logic_test.sh` 覆盖，包括：两个阈值各自的前后 1 毫秒边界、
活动必须重置计时而非仅清状态、置 0 禁用该级、32 位 tick 回绕、
off 阈值小于 dim 阈值时的钳位、以及 NULL 安全。

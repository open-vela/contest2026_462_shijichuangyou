配套 `docs/UI_REDESIGN.md`。以下项目在本文写作时全部为 **NOT_RUN**，需要在真机上
逐项确认后才可改写状态。不要把本清单的存在当成已通过。

## 烧录

**当前环境无法自动烧录**（2026-09-17 实测）：

- `/dev/ttyUSB0` 权限为 `crw-rw---- root dialout`，即 `660`；
- 用户 `ran` 的组为 `ran,adm,cdrom,sudo,dip,plugdev,users,lpadmin`，**不含 `dialout`**；
- `getent group dialout` 返回 `dialout:x:20:`，该组当前**没有任何成员**；
- 直接打开设备返回 `PermissionError [Errno 13] Permission denied`；
- `sudo` 不可用：`sudo: The "no new privileges" flag is set, which prevents sudo
  from running as root.` 因此无法临时提权，也无法 `usermod` 把自己加进组。

一次性修复（需要用户在自己的终端执行，之后**重新登录**才生效）：

```sh
sudo usermod -aG dialout $USER
```

烧录地址 `0x12010000` 来自板级 README，不是推测值。
**注意路径**：`sftool` 只在工作区根目录的 `.tools/` 下，`openvela/.tools/` 不存在。

```sh
cd /media/ran/EXTERNAL_USB/watch
.tools/sftool-0.2.5/sftool -c SF32LB52 -p /dev/ttyUSB0 -b 1000000 \
     --before default_reset --after soft_reset \
     write_flash openvela/cmake_out/ebadge_app/nuttx.bin@0x12010000
```

固件：`openvela/cmake_out/ebadge_app/nuttx.bin`，9,458,652 字节。
板级 README 里写的是 `cmake_out/lckfb_huangshan_pi/nuttx.bin`，那是 README 自己的
构建目录名，与本项目的 `ebadge_app` 不是同一路径，不要照抄。
若报 `Failed to connect to the chip`，拔插 USB 重试；若反复只打印 `SFBL`，
说明 AMOLED 拉低了 USB 供电，改用 5V/2A 充电器或电池。

烧录后可用 `python3 tools/board_nsh.py` 读取 NSH 输出，同样受上述串口权限限制。

## 内存卡（独立于 UI）

先单独验证卡本身，脚本见 `tools/probes/sdcard.txt`：

```sh
python3 tools/board_nsh.py --script tools/probes/sdcard.txt
```

关注 `mount` 是否成功、`ls` 是否列出内容、`dd` 写入后 `cat` 能否读回。
历史上无卡时 `/dev/mmcsd0` 读失败（`infd open failed: 5`，EIO）。

**结论**：全部矩形在画布内（最大 x=380、最大 y=446），未发现意外重叠。分层按创建
顺序确定：立绘 → 渐隐 → 名字/文案/指示点 → 提示气泡 → 纹样 → 功能页
（头像 → 气泡+尾巴 → 内容卡 → 星光 → 格言 → 按钮）→ 菜单，与设计意图一致
（渐隐和文字必须在立绘之上，功能页必须盖住提示气泡）。两处星光压在卡片圆角缺口上
属刻意安排——卡片圆角半径为 22 px，该处本就无填充。

**字号约束（易错点）**：`lv_font_montserrat_48` 的 `fallback = NULL`，不含任何中文
字形。凡使用该字体的大字号标签**只能放数字、冒号与短横线**；中文必须落到 20 px 中文
的那一行。纪念日页曾把"今天"放进大字号，会渲染成空白——这正是静态审计看不出、
只有靠约束记录来防的一类问题。

**这不替代真机观察**：几何正确不代表字号、对比度、触摸手感、动画流畅度正确。
下列仍需真机确认。

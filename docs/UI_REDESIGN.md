# eBadge 交互与界面改版

本文件记录本轮 UI/UX 改版的设计依据、实现边界和验证状态。设计来源是仓内
已评审的浏览器原型 `design/interactive/`；`INTERACTION_SPEC.md` 明确写了
"板端迁移尚未完成"，本轮把它落到 LVGL 固件上。

## 为什么改

改版前的板端界面存在四个直接影响可用性的问题：

1. **主屏没有任何可发现性提示**。`footer`、`dots`、`heading` 在创建后立刻被
   置为隐藏，用户看到立绘、名字和一句文案，无从得知可以点、可以滑、有几个角色。
2. **导航模型弱**。上下滑动线性循环 5 个页面，看不到当前位置，没有返回，访问
   最后一页必须滑 4 次。
3. **角色与视觉脱节**。3 套配色是全局的，与角色无关；切角色配色不变。
4. **反馈不一致**。只有苔苔有帧动画（`character != 0` 时动画被暂停），
   点暖暖和月月没有任何响应。

## 交互契约（板端已实现）

设计画布 390 × 450，按实际面板分辨率等比缩放。手势阈值以画布单位定义。

| 操作 | 结果 |
| --- | --- |
| 轻点角色（位移 ≤ 10，且在 600 ms 内） | 角色专属纹样回应（花叶／猫爪／星光），立绘本身不移动 |
| 左右滑（≥ 55 px，且横向占优 ≥ 1.35 倍） | 切换苔苔／暖暖／月月，立绘横向滑入 |
| 上滑（≥ 60 px，且纵向占优 ≥ 1.35 倍） | 打开底部小册菜单 |
| 长按 600 ms（位移 ≤ 10） | 打开底部小册菜单 |
| 点菜单项 | 进入时钟／文字应援／纪念日／配色 |
| 点菜单空白处或"收起" | 关闭菜单 |
| 点页面左上"返回" | 回到角色主屏 |

规则：菜单或功能页打开时，主屏手势全部失效；编辑器浮层内的输入不会触发主屏手势。

## 设计令牌

配色从原型的每角色一套改为令牌化，见 `app/hello_app/ui/ebadge_theme.c`。

| 角色 | 纸色 | 墨色 | 点缀 | 纹样 |
| --- | --- | --- | --- | --- |
| 苔苔 | `#f7f3e6` | `#405334` | `#af9962` | 花叶 |
| 暖暖 | `#fff1df` | `#68442d` | `#bb854c` | 猫爪 |
| 月月 | `#edf0f7` | `#344967` | `#ad9b70` | 星光 |

底色三选一：`随角色`（跟随角色）、`素纸`（`#f8f6ef`）、`夜读`（`#222a31`）。
两套通用底色只替换纸色／墨色／柔和色，点缀色始终保留角色自身，使角色在任何
底色下仍可辨认。夜读只改界面底色，不改变立绘颜色。

## 界面清单

- **主屏**：立绘 + 底部渐隐遮罩 + 衬线体角色名 + 角色文案 + 3 个角色指示点；
  首次启动显示 7 秒手势提示气泡后淡出。壁纸之外不常驻任何按钮。
- **小册菜单**：底部弹出面板，衬线体标题"随身小册"、收起按钮、四项功能入口。
- **时钟（心动时刻）**：页头角色头像牌 + 对话气泡（按 5/11/17/22 点分四段说不同的话）
  ／圆角卡片内 48 px 时间与年月日星期／金色格言／两处星光。
- **文字应援（把喜欢说出来）**：同样的页头与气泡，卡片内环形滚动文案，下方"写一句新的"。
- **纪念日（值得记住的日子）**：气泡按"未设置／未校准／已设置"说不同的话，
  卡片内 48 px 天数，副行显示目标日期与"还有／已经走过／就是今天"。
- **配色（你的收藏）**：角色三选一 + 底色三选一，选中项用角色强调色点亮，
  实时预览，并显示存储状态。
- **编辑器**：沿用原有日期编辑器和文字编辑器，配色改为跟随新令牌。

## 二次元（插画风）改版

首版页面是"设置表单"的观感：一行小标题、一个大数字、一行说明、一个按钮。
功能齐全，但不像角色自己的屏幕。这一轮按 ACG 插画风重做。

### 视觉语言

新增 `ui/ebadge_deco.c`，把可复用的插画构件集中到一处：

| 构件 | 实现 | 用途 |
| --- | --- | --- |
| 对话气泡 `ebadge_deco_bubble` | 圆角卡片 + 旋转 45° 小方块作尾巴 | 角色"说话"的容器 |
| 星光 `ebadge_deco_sparkle` | 两条交叉圆角细条，纯图形绘制 | 角落点缀与闪烁 |
| 头像牌 `ebadge_deco_avatar` | 圆角方框 + 内嵌立绘缩放 | 页头的角色在场感 |
| 贴纸标签 `ebadge_deco_chip` | 全圆角药丸 | 状态短语 |

尾巴用**旋转 45° 的方块**而不是三角形，因为 LVGL 没有三角形图元。关键点：
LVGL 默认把子对象裁剪到父对象内，`LV_OBJ_FLAG_OVERFLOW_VISIBLE` **不是默认值**，
不显式设置的话尾巴根本画不出来。

### 角色语气

时钟页不再像报时器。新增 `ebadge_theme_daypart()` / `ebadge_theme_greeting()`，
按 5/11/17/22 点分四段，每个角色每段一句自己的话：

- 苔苔（晨）："早上好呀，今天也要好好生长哦。"
- 暖暖（午后）："这种天气最适合窝着晒太阳。"
- 月月（夜）："月亮升起来了，早点休息吧。"

同一时刻切换角色，页面说的话会跟着变——这是行为，不是装饰。

### 装饰字形

GB2312 只有 ☆★○●◎◇◆△▲※ 这类，**没有 ♡ ♪ ✿**。对 Noto Sans CJK SC 实测后
加入 `DECORATION = ♪♫♡♥✿❀▽▼✓`；`✧✦☾☽⋆✩` 在该字体中不存在，因此不可使用。
正文位图从 715,486 涨到 716,908 字节，仍在 LVGL 20 位上限 1,048,575 之内。

### 交互增强

- **按下反馈**：按钮在 `LV_STATE_PRESSED` 下降不透明度到 70% 并缩放到 240/256。
  面板是电阻屏且无振动马达，按钮必须自己确认触摸。
- **入场动画**：页面自下方 18 px 上移并淡入（200 ms ease-out），不再是硬切。
- **星光闪烁与头像呼吸**：**有限次数**（3 / 2 个循环）后停止。刻意不用无限循环，
  否则会持续触发重绘，与 FR-08「空闲熄屏」冲突。

### 这一轮修掉的缺陷

- 气泡尾巴创建时用占位黑色填充，而 `apply_theme()` 只改气泡主体颜色，尾巴不跟着变。
- 页头头像在 `open()` 时固定用角色 0 的立绘，切换角色后不更新。
- 纪念日页把中文"今天"塞进 `lv_font_montserrat_48`。该字体 `fallback = NULL`、
  无中文字形，会渲染成空白。现改为大字号只放数字，中文全部落到 20 px 中文那一行。

## 字体

原字体是 138 个汉字的子集，`CHINESE_UI.md` 明确写着"不覆盖任意用户输入"。
本轮改为可复现的生成流水线：

```sh
python3 tools/generate_font.py          # 重新生成两个字面
python3 tools/verify_font_coverage.py   # 校验所有字面量都有字形
```

- 正文：Noto Sans CJK SC 20 px，**GB2312 一级字库 3755 字 + 标点 + ASCII**，共 4025 字形。
- 标题：Noto Serif CJK SC 26 px，151 字形（仅标题用字）。

**字形集大小由 LVGL 决定，不是由 flash 决定**：`lv_font_conv` 默认把字形偏移
打成 20 位字段，整个字体的位图必须小于 1 MiB，否则编译期报
`Too large font or glyphs ... Enable LV_FONT_FMT_TXT_LARGE`。一级字库位图
715,486 字节可通过；加入二级字库会到 1.27 MB 而失败。启用该 LVGL 选项是影响
所有字体的全局改动，因此默认停在一级字库。这一约束由
`tools/verify_font_coverage.py` 在生成后立即检查，不必等到编译。

`tools/verify_font_coverage.py` 会扫描应用源码中所有字符串字面量里的宽字符，
与生成字体的 cmap 求差集。改动文案而忘记重新生成字体时，它直接失败，而不是
在面板上画成方框。

## 存储

见 `core/ebadge_store.h`。角色、底色、应援文案、纪念日、时区可以存到内存卡；
卡不在或不可用时全部退回本次运行有效的 RAM 行为，界面如实显示当前状态
（`ebadge_store_status()`），不假装已保存。

- 挂载点 `/data/sdcard`（`/data` 是可写 tmpfs，根是只读伪文件系统）。
- 设备 `/dev/mmcsd0`，`vfat`；构建已启用 `CONFIG_MMCSD`（SPI 模式）与 `CONFIG_FS_FAT`。
- 写入先落 `ebadge.tmp` 再 `rename`，断电不会留下半截设置文件。
- 文件带 magic、版本和校验和；校验失败按"无设置"处理，不猜测。
- 改动后延迟 1.5 秒落盘，避免连续滑动时反复写卡。

## 纯逻辑主机测试

```sh
sh tools/run_logic_test.sh
```

覆盖三块**在面板上看不出对错**的纯逻辑，用宿主 `cc` 编译，不需要 LVGL 也不需要板子：

- `core/ebadge_record.c`：内存卡设置记录的编解码。校验 magic、版本、字段偏移、
  校验和、消息字段的 NUL 终止、以及**日期是否为真实日历日**。其中一项是把
  174 个受校验字节逐位翻转 8 次（1392 组），确认没有一组漏检。
- `core/ebadge_calendar.c`：纪念日天数计算。跨闰日边界、跨年、正反向、
  2024–2099 全区间「逐月累加天数」与「序数差」必须一致，以及 2024–2025
  连续 730 天的序数必须逐日 +1。
- `ui/ebadge_theme.c`：问候语分段与调色板不变量。检查 5/11/17/22 四处分界点
  两侧、越界小时的钳位、每个角色日夜必须说不同的话（否则时钟页的问候只是
  装饰而非行为）、角色名不重复、以及**底色模式不得覆盖角色强调色**
  （这是"角色在任何底色下都可辨认"这条设计约束的可执行形式）。

这三个模块原本分别是 `ebadge_store.c`（带 `<sys/mount.h>`）、`ebadge_pages.c`
里的 `static` 函数和 `ebadge_theme.c`（未纳入测试），无法单独编译，因此此前
没有或被部分验证。现在它们不依赖文件系统与 LVGL，可以独立测试。

抽取过程中修掉的真实缺陷：

- 原 `decode()` 只校验 `day <= 31`，会接受 `2026-02-30`、`2026-04-31` 这类
  不存在的日期；现在用 `ebadge_date_valid()` 按真实月长校验。
- 原 `decode()` 硬编码 `>= 3` 作为角色/底色上界，改为 `EBADGE_CHARACTER_COUNT`
  与 `EBADGE_PAPER_COUNT`，避免枚举扩展后静默失配。
- 三处各自复制了闰年与月长逻辑（`ebadge_pages.c`、`ebadge_date_editor.c`、
  `ebadge_store.c`），现已统一到 `core/ebadge_calendar.c`。
- `ebadge_days_between()` 用 0 同时表示「同一天」和「输入非法」，已在头文件
  标注该歧义，并要求调用方先校验范围；`paint_anniversary()` 确实先校验了。

# 时钟持久化（RTC）

解决"每次冷启动时间都回到未校准"的问题。

## 驱动与接口（取自源码）

| 项 | 值 | 依据 |
| --- | --- | --- |
| 设备节点 | `/dev/rtc0` | `drivers/timers/rtc.c` 用 `snprintf("/dev/rtc%d", minor)` 注册 |
| 板级注册 | `rtc_initialize(0, sf32lb_rtc_lowerhalf())` | `vendor/sifli/boards/sf32lb52/lckfb_huangshan_pi/src/sifli_ap.c`，守卫为 `CONFIG_RTC && CONFIG_RTC_DRIVER`（均已开） |
| 读时间 | `ioctl(fd, RTC_RD_TIME, &rtc_time)` | `include/nuttx/timers/rtc.h` |
| 写时间 | `ioctl(fd, RTC_SET_TIME, &rtc_time)` | 同上 |
| 是否设过 | `ioctl(fd, RTC_HAVE_SET_TIME, &bool)` | 同上 |

`struct rtc_time` 与 `struct tm` **可互相转换**（`include/time.h` 明确说明），
所以用 `timegm()` 转 epoch、`gmtime_r()` 转回来。`timegm`/`clock_settime` 在本
NuttX 树中均存在，非臆造。

## 为什么需要它

在此之前应用只用 `time(NULL)` 读系统时钟，而**系统时钟只有在主机通过串口执行过
`date` 的那一次会话里才是对的**。于是：

- 时钟页显示不出真实时间，只能显示"我还没对上时间"；
- 纪念日页走 `local_now()` 的有效性判断（年份须在 2024–2099），冷启动后
  恒为无效，只能显示"时间尚未校准"。

接入后：**用主机对一次时间，之后徽章自己记得。**

## 同步方向与安全规则

方向判定在 `core/ebadge_rtc_logic.c`，是纯函数并有主机测试，因为**错在这里的后果
是灾难性的**：把未设置的系统时钟（1970）写进好好的 RTC，会毁掉唯一一份正确时间，
而且在下次开机前完全看不出来。

| 系统时钟 | RTC | 动作 |
| --- | --- | --- |
| 无效 | 无效 | **什么都不做**（绝不凭空造一个时间） |
| 无效 | 有效 | **RTC → 系统**（开机主路径） |
| 有效 | 无效 | **系统 → RTC**（主机刚对过时间，落盘） |
| 有效 | 有效，偏差 ≤ 60s | 什么都不做（是漂移，不值得反复写总线） |
| 有效 | 有效，偏差 > 60s | **系统 → RTC**（判定为主机刻意校正） |

年份有效范围 2024–2099，与时钟页 `local_now()` 的判定完全一致，避免两处对
"已校准"的理解不一致。

## 调用时机

`ebadge_main.c` 在 **LVGL 初始化之前**调用 `ebadge_rtc_sync()`，因为时钟页第一次
绘制就要读它。结果打到串口日志：

```
ebadge: 时钟：已由 RTC 恢复 (action 2)
```

**未在配色页加状态行**：该页状态行已排到 y=408，再加一行会超出 450 高的画布。
RTC 是否生效直接看时钟页有没有真实时间即可，这本身就是最好的证据。

## 未验证点（必须真机确认）

- `/dev/rtc0` 在本固件中是否真的注册成功（板级注册代码存在，但**未实测**）；
- **RTC 是否掉电保时**：取决于 SiFli 的常开域是否有备份供电。若整机断电后
  RTC 归零，则本机制只能跨"热重启"保时，不能跨"拔电"保时。这一点**未确认**，
  不应对外宣称"断电不丢时间"；
- `RTC_HAVE_SET_TIME` 在本板驱动上是否真正实现（若未实现，代码退化为仅靠年份
  范围判断，仍然安全）；
- 是否需要周期性把系统时间回写 RTC（当前只在启动时同步一次）。
